registry-proxy has been deployed.

Check the pod status with:
  kubectl get pods -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ .Release.Name }}

Registry API inside the cluster:
  http://{{ include "registry-proxy.fullname" . }}.{{ .Release.Namespace }}.svc:{{ .Values.service.port }}/v2/

Port-forward the API for local checks:
  kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "registry-proxy.fullname" . }} 5000:{{ .Values.service.port }}
  curl http://127.0.0.1:5000/v2/

The proxy accepts three equivalent client forms and normalizes them to the same
local repository:
  path:  /v2/ghcr.io/org/app/manifests/v1
  host:  Host: ghcr.io + /v2/org/app/manifests/v1
  ns:    /v2/org/app/manifests/v1?ns=ghcr.io

The optional routing table is stored at
/var/lib/registry/registry-mapping.yaml inside the container, derived from the
registry configuration's filesystem root. Set REGISTRY_MAPPING_PATH to override
it.

The Service also exposes port 443 to the same plain-HTTP backend. This is not
a TLS endpoint: it lets clients that probe HTTPS first fail fast and retry over
HTTP. Ingress uses the HTTP service port above; optional Ingress TLS is
terminated by the Ingress controller.
